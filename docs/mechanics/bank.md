# Bank

Scope: the bank interface and its item rules (`content/gameframe`: `Bank`, `BankLayout`, `BankDrag`). Behaviour source for
every row is RS Mod v2 `content/interfaces/bank` (https://github.com/rsmod/rsmod, ISC; clone read at 2026-11-06), cited as
`BankInvScript:line`, `BankOpenScript:line`, `BankSettingsScript:line` (files under
`content/interfaces/bank/src/main/kotlin/org/rsmod/content/interfaces/bank/scripts/`), unless the OSRS Wiki
(https://oldschool.runescape.wiki/w/Bank, `/w/Bank_placeholder`, `/w/Banker`) is named. Component, varbit, varp and param ids
are our gameval symbols (cache 2757) and `cache-dump`; RS Mod's rev differs from ours in component numbering, so roles were
matched by name and the op lists checked with `cache-dump interface 12`. No code was copied (DECISIONS D-029). A button
click is one IF_BUTTON packet handled in the player's input phase of the tick it arrives in; every row's item change is one
`PlayerRef.transaction` (brief §12), sent to the client as inventory updates at the end of that tick. A count dialog ("X")
answers on a later tick and re-checks the slot, the obj and that the bank is still open before it acts.

Interfaces: `bankmain` (12) as the main modal and `bankside` (15) in side slot 3 over the backpack (the borrowing described in
gameframe-buttons.md Q1; a once-per-tick `ModalWatch` puts the backpack back). Inventories: `bank` (95, stack always, 1410
slots in the cache), `inv` (93), `worn` (94).

## Not implemented

- **OPEN-B4** Bank-side extra ops (wear, eat/drink, rune pouch, looting bag, seed box), because wielding is content/combat's
  `wield`, which interrupts (closes the modal); it needs an entry point that keeps the modal open.
- **OPEN-B5b** Bank fillers, the potion store, bank tags/loadouts, "Empty containers", the worn-items page's bonus texts
  (`bankmain:stabatt` ...), the confirmation popups of "Release all placeholders" / incinerator (client script 4212 in RS Mod
  is not verified for rev 242; releases happen at once), bank PIN, and the chatbox tooltip on the capacity.
- **OPEN-B6** Worn deposit/removal leaves `combat_weapon_category` and the special-attack bar as they were; content/combat
  refreshes them only when it moves the item itself.
- **OPEN-B7** Drag operations (B10-B12) are written against the layout but nothing calls them: the protocol adapter drops
  IF_BUTTOND and the engine has no drag handler (PROGRESS.md, deferred from Phase 3).
- **OPEN-B8** Sub-component ids of `bankmain:tabs` (10, 11..19) and the extra drop-target slots after the last bank slot are
  created by the client's scripts, not by the interface definition; they are RS Mod's values for its revision.
